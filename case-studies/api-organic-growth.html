Case study 01 · API platform

From about 30 to 3,000+ monthly organic visits in under five months.

The biggest change was not publishing more for the sake of it. It was connecting related API topics into a system around search intent and core use cases.

Starting point

The site had very little organic traffic and disconnected topic coverage.

The API platform was sitting at roughly 30 monthly organic visits. Instead of treating every keyword as a separate assignment, the opportunity was to build enough connected coverage around the product’s core use cases that both search engines and buyers could understand what the platform was relevant for.

What we changed

Related topics were grouped around intent and use cases.

The content plan used topical clusters and pillar pages. Each piece had a place in the larger structure, and internal links connected supporting articles back to the main subjects.

What shaped the roadmap

  • Keyword and competitor gaps around core API use cases.
  • Different search intents: education, troubleshooting, comparison, pricing, and commercial evaluation.
  • Pillar pages and supporting articles rather than isolated keyword targets.
  • Business relevance alongside search demand.

Execution

The work continued after publish.

My work covered keyword research, cluster planning, briefs, production, internal linking, and performance review. The content itself included API management, pricing, frameworks, marketplaces, comparisons, and troubleshooting topics.

Pages that underperformed were reviewed and refreshed rather than automatically replaced with another new article.

Result

Monthly organic traffic grew from about 30 to 3,000+.

A content calendar is not enough by itself.

This is the clearest example of how I prefer to work: decide which topics matter, connect them properly, make the production process repeatable, and use performance data to decide what deserves attention next.
